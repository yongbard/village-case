# 마을 수사록 UI 다시 그리기 — 서류철 물건으로

작성: 2026-11-25. 앞선 설계: docs/2026-11-24-casefile-ui-design.md (서류철 분위기, 인물 사진), docs/2026-11-25-readability-design.md (글꼴·진술 말투). 게임 규칙·엔진·스테이지·진술 문장은 그대로.

## 1. 왜 하는가

사용자 말: "전체적으로 UI 고도화, 이미지는 괜찮으나 나머지 웹 UI가 AI slop임". 방향은 "알아서 벤치마킹해서 판단"하라고 Claude 에게 맡겼다.

인물 사진과 코르크판에 핀으로 꽂은 카드는 진짜 물건처럼 보인다. 그 밖의 것(메뉴, 머리 정보, 꼬리표, 진술 기록, 창, 결과, 도감, 규칙)은 흔한 웹 템플릿처럼 보인다. 이번 일은 사진 밖의 화면도 서류철 안의 물건으로 보이게 다시 그리는 것이다.

지금 화면에서 템플릿처럼 보이는 것 (흔히 꼽히는 AI 디자인 증상과 같다)
- 모든 것이 같은 크림색 둥근 상자 + 그림자 (제목 메뉴, 장 묶음, 메모 줄, 진술 기록, 도감 항목, 규칙 개념 상자).
- 왼쪽 굵은 색 띠: 주 단추(btn.primary), 말풍선(bubble).
- 알약 모양 꼬리표: 직업 꼬리표(chip), 진술 줄의 선·악 꼬리표, 도감의 진영 꼬리표.
- 색 동그라미 안 숫자: 결과 화면 수사 보고서 단계.
- 대시보드처럼 늘어놓은 숫자(경과·평판), 같은 굵기·크기의 굵은 고딕이 화면 대부분.
- 메모 줄의 직업 목록과 그 아래 직업 꼬리표가 같은 내용을 두 번 보인다.

## 2. 벤치마크

- Clues by Sam (같은 장르의 웹 퍼즐, 4×5 격자 인물을 자연어 진술로 가림): 장식 없이 격자와 글자만. 읽기 쉬움의 기준으로 삼는다.
- The Case of the Golden Idol, Return of the Obra Dinn, Shadows of Doubt: 화면 자체가 수첩·서류철·코르크판 같은 실제 물건(diegetic). 분위기의 기준으로 삼는다.
- 위 게임들의 그림·화면을 베끼지 않는다. 가져오는 것은 원리뿐: "화면 요소마다 그것이 무슨 물건인지 정해져 있다", "물건은 그 물건답게 생겼다(양식은 칸과 괘선, 공책은 줄, 도장은 잉크)".

## 3. 방법 (Claude 가 고름, 사용자가 판단을 맡김)

1. 서류철 물건으로 다시 그리기 — 고름. 사진 밖의 요소마다 물건 하나를 정한다(목차, 양식, 줄 공책, 색인 카드, 고무도장, 쪽지). 둥근 상자를 없애고 괘선·여백·글자 위계로 구분한다. 11-24 에 사용자가 고른 서류철 분위기와 지금 사진을 그대로 살린다.
2. 글자만 남긴 하얀 지면(Clues by Sam 쪽) — 안 씀. 깔끔하지만 사용자가 고른 서류철 분위기를 버리고, 빛바랜 사진과 어울리지 않는다.
3. 지금 틀에서 다듬기(색 띠·둥근 모서리만 걷기) — 안 씀. 싸지만 "상자 늘어놓기" 구조가 남아 사용자가 지적한 문제의 뿌리가 그대로다.

시안: docs/mockups/2026-11-25-paper-screens.png (타이틀, 사건, 칸 메뉴, 결과 네 화면). 원본 docs/mockups/2026-11-25-paper-src.html, 찍는 도구 docs/mockups/2026-11-25-render.mjs (인물 사진을 넣어 png 로 찍음). 시안은 방향을 보이는 것이고 픽셀 값의 기준은 아니다.

## 4. 목표 / 비목표 / 실패 조건

목표
- 모든 화면(타이틀, 스테이지 목록, 사건, 칸 메뉴·직업 창·인원표 창, 힌트·안내·능력 고르기 쪽지, 결과, 인물 카드철, 수사 규칙, 불러오는 중, 새 직업 카드)에서 요소마다 무슨 물건인지 정해져 있고, 그 물건답게 생겼다.
- 1장의 템플릿 증상이 남지 않는다.
- 사건 화면 머리의 중복(메모 줄 직업 목록 + 직업 꼬리표)을 하나로 합친다.

비목표
- 게임 규칙, 사건 생성, 솔버, 진술 문장, 저장 형식, 스테이지 내용의 변경.
- 인물 사진(portraits.ts)과 판 카드(핀, 기울기, 뒷면, 체포 도장, 포스트잇 메모)의 모습. 사용자가 괜찮다고 했다. 칸 번호 글꼴만 바뀔 수 있다(6장).
- 새 화면·새 기능, 소리, 다크 모드.
- 그림 파일(png 등) 재질. 재질은 지금처럼 CSS 로만.

실패 조건 (돌아가도 실패로 본다)
- 장식 때문에 진술을 읽기 힘들어진다. 진술·본문 글자는 15px 이상, 지금보다 작아지지 않는다.
- 작은 양식 라벨이 12px 보다 작다(시안의 11px 은 쓰지 않는다).
- 폰(390×844)에서 가로 스크롤, 누르는 자리 44px 미만.
- 오프라인에서 글꼴이 빠진다.
- 둥근 상자·왼쪽 색 띠·알약 꼬리표·색 동그라미 숫자가 다른 모습으로 다시 나타난다(예: 모서리만 각지고 여전히 그림자 상자를 늘어놓음).
- 선·악을 색으로만 구별한다(지금처럼 글자로도 보인다).

## 5. 제약

- 화면 기준, 여백, #app 최대 폭 430px, 동작 줄이기 설정은 11-24 설계 3장 그대로.
- 화면 확인 도구 check-ui 가 쓰는 data-* 속성(data-action, data-cell, data-stage, data-stat, data-result, data-hint, data-line, data-note, data-seed-msg 등)은 유지한다. 클래스 이름이나 구조를 바꾸면 check-ui 를 같이 고친다. 끝나면 check-ui 전체 OK, 확인 항목 수가 줄어들면 안 된다(합친 요소의 확인은 새 모습에 맞게 옮긴다).
- npm test, 타입 검사, 빌드, check-offline 통과.
- 글꼴 저작권: 새 글꼴도 SIL OFL 만. 예약 이름이 있으면 이름을 바꿔 낸다(지금 Village Sans·Village Hand 와 같은 방식).
- 글꼴 합계 지금 380KB, 1MB 이하 유지.

## 6. 물건 사전 (화면 요소 → 물건)

모든 화면이 아래 물건만 쓴다. 같은 물건은 어디서나 같은 모습이다.

재질 규칙
- 종이는 각진다. 둥근 모서리는 핀·사진기 렌즈 같은 둥근 물건에만.
- 그림자는 코르크판(또는 어두운 창 뒤) 위에 놓인 물건에만 한 겹. 종이 위의 요소는 그림자 없이 괘선·여백·글자로 구분한다.
- 잉크 색은 넷: 먹(본문), 빨간 도장 잉크(체포·주범·결정), 파란 볼펜(플레이어가 쓴 메모), 옅은 연필(보조 글). 연두·분홍 같은 배경 칠은 쓰지 않는다. 선 진영의 초록은 "선" 도장 잉크로만 남긴다.
- 기울기는 코르크판 위 종이에만 ±1도 안. 종이 위 요소는 똑바로.

물건
- 목차: 한 줄 = 쪽 번호(고정폭) + 이름(송명) + 점선 이음 + 값(고정폭) + ›. 줄 사이 점선, 첫 줄 위 먹선. 한 줄 높이 56px 이상. 타이틀 메뉴, 결과 화면 아래 이동에 쓴다.
- 양식: 작은 라벨(12px, 연필색)이 칸 왼쪽 위, 값은 그 아래. 칸은 1px 먹선 표. 사건 머리, 결과 보고서 머리, 시드 입력(밑줄 칸)에 쓴다.
- 줄 공책: 파란 괘선 + 왼쪽 빨간 여백선, 여백에 칸 번호(고정폭). 글줄이 괘선에 앉는다(줄 높이 = 괘선 간격). 진술 기록, 칸 메뉴의 진술 인용에 쓴다.
- 색인 카드: 위쪽 빨간 선 하나, 아래 파란 괘선. 아래에서 올라오는 창(칸 메뉴, 직업 창, 인원표 창), 새 직업 카드, 인물 카드철 항목에 쓴다.
- 고무도장 단추: 각진 잉크 테두리, 송명 글자, 자간 넓게. 결정하는 단추에만(체포 = 빨간 이중 테두리, 조사·열람 등 = 먹 테두리). 눌렸을 때 잉크가 살짝 번지는 모습(배경 옅은 잉크)으로, 아래로 꺼지는 그림자 효과는 쓰지 않는다. 쓸 수 없을 때는 흐린 연필색.
- 도장 표시(누르는 자리 아님): 해결·미해결·체포·오인 체포, 진술 줄 끝의 판정(선·악), 직업의 진영 표시(주범·공범·말썽꾼). 작은 사각 잉크 테두리, 송명.
- 쪽지: 노란 포스트잇(손글씨 머리말) 또는 테이프로 붙인 종이 조각. 힌트·안내·능력 고르기 말풍선, 힌트 탭에 쓴다. 왼쪽 색 띠 없음.
- 형광펜: 표시된 진술(지금 분홍 배경)은 글줄 아래쪽 절반만 칠한 노란 형광펜으로.
- 글자 단추(링크): 밑줄 글자. 나가기, 다시 하기, 사건 목록, 인원표 전체, 직업 이름(점선 밑줄, 지금 그대로) 같은 가벼운 이동.

글꼴 (11-25 에 정한 셋 + 숫자 하나)
- 제목·도장·목차 이름: 송명.
- 본문·진술·라벨: Village Sans(IBM Plex Sans KR). 굵은 글씨는 직업 이름처럼 짚어야 할 말에만. 문단 전체를 굵게 하지 않는다.
- 메모·쪽지 머리말: Village Hand.
- 숫자(칸 번호, 쪽 번호, 사건 번호, 경과·평판·체포 값, 시드): 고정폭 숫자 글꼴을 새로 넣는다. IBM Plex Mono 의 숫자·영문·문장부호만 남긴 부분 집합을 Village Mono 로 이름 바꿔 낸다(Plex 예약 이름). 한글이 섞이면 Village Sans 로 보인다.

## 7. 화면별

타이틀 (시안 ①)
- 서류철 표지는 지금 그대로 두되, 라벨 종이 머리에 "사건 서류철 · No. 0030"처럼 양식 줄(고정폭 번호)을 둔다. 둥근 모서리를 걷는다.
- 메뉴 단추 넷 → 테이프로 붙인 목차 한 장: 01 사건 파일 (0 / 30), 02 끝없는 수사 (최고 기록), 03 인물 카드철 (만난 수 / 28), 04 수사 규칙. 이어 하기 같은 지금 있는 단추·기능은 목차 줄로.
- 시드 입력 → 같은 종이 아래 양식 칸 "사건 코드로 열기 ____" + 먹 도장 단추 "열람". 오류 글은 칸 아래 빨간 잉크.

스테이지 목록
- 장마다 테이프로 붙인 종이 한 장(지금의 둥근 카드 대신). 머리: "제1장" (송명) + 고정폭 "01 – 05".
- 스테이지는 원고지 같은 정사각 칸 5개 한 줄, 칸 사이 1px 먹선. 칸 안에 고정폭 번호 크게, 아래 판 크기(3×3).
- 푼 것: 칸 위에 빨간 동그라미 확인 도장 "해결". 지금 할 것: 연필 동그라미. 잠긴 것: 흐린 번호 + 칸에 사선 한 줄(색 말고 모양으로도 구별), 누르는 자리 아님.
- 지금의 마닐라 파일 모양 칸은 버린다.

사건 화면 (시안 ②)
- 맨 위 코르크판 위: "‹ 나가기"(글자 단추), 제목(송명, 예: 사건 제14호 / 1스테이지), 오른쪽 힌트는 판 가장자리에 붙은 노란 쪽지 탭(손글씨 "힌트", 남은 힌트 수가 있으면 같이).
- 그 아래 사건 양식 한 장(지금 stats 메모 줄 + 직업 꼬리표를 합친 것):
  - 윗줄 표 세 칸: 경과(고정폭 + "시간"), 평판, 체포한 주범(빨강, "0 / 2"). 평판이 낮으면 값을 빨간 잉크로(지금 low 처럼).
  - 아랫부분 "이 마을에 숨은 직업" 명단: 증인을 뺀 직업이 두 칸씩 줄로. 한 줄 = 직업 이름(굵게) + 진영 도장 표시 + 오른쪽 "×2". 줄 전체가 누르는 자리(44px 이상)이고 누르면 지금 꼬리표처럼 직업 창. 오른쪽 위 글자 단추 "인원표 전체"는 지금 인원표 창.
  - 직업이 많아 두 칸에 넘치면 줄이 늘어난다(30스테이지 7개면 4줄).
- 판: 지금 그대로(물건 사전 밖). 칸 번호만 고정폭.
- 진술 기록: 테이프로 붙인 줄 공책 한 장. 머리 "진술 기록"(송명) + 고정폭 "8 / 16명". 줄마다 여백에 칸 번호, 본문에 직업 이름(점선 밑줄, 지금처럼 누르면 직업 창) + 진술. 체포로 판정된 줄은 글을 연필색으로 낮추고 끝에 작은 판정 도장(선/악). 자백 줄, 표시된 줄(형광펜)은 지금 기능 그대로.
- 힌트·안내·능력 고르기 말풍선(panel): 노란 쪽지 또는 테이프 붙인 종이. 손글씨 머리말("힌트", "안내"), 쪽수(고정폭), 이전·다음은 글자 단추.

아래에서 올라오는 창 (시안 ③)
- 칸 메뉴: 색인 카드. 머리에 기운 사진(흰 테두리, 지금 sheet-photo), 라벨 "5번 칸 · 조사함", 직업 이름(송명 크게). 진술은 따옴표 + 괘선 위 인용. "약사는 어떻게 말하나" 글자 단추. 조사·체포는 고무도장 단추 두 개(60px 높이). 메모는 한 줄 양식 "내 메모 | 선 | 악 | ? | 지우기", 칸 사이 먹선, 고른 칸은 포스트잇 노랑 + 파란 손글씨.
- 직업 창·인원표 창: 같은 색인 카드. 인원표의 표는 양식 표로.
- 닫기는 글자 단추.

결과 (시안 ④)
- 테이프로 붙인 수사 보고서 한 장. 머리 양식 줄 "수사 보고서 · 사건 No. 0001", 제목 "보고서"(송명, 자간 넓게), 표 세 칸(경과, 남은 평판, 체포한 주범).
- 큰 도장: 해결(빨강) / 미해결(먹). 지금 연출 그대로.
- 해설 단계: 여백에 고정폭 단계 번호 "01", 본문 "1번은 선 — …". 주범을 정하는 단계는 빨간 글자. 색 동그라미 숫자는 버린다. 능력 목록(abilities)도 같은 지면 안의 글로.
- 아래: "다음 사건  No. 0002 →" 먹 테두리 목차 줄 하나(주 이동), 그 밑 글자 단추 "다시 하기 · 사건 목록". 무한 모드 결과도 같은 틀(값만 다름).

인물 카드철 (도감)
- 만난 직업: 색인 카드 한 장. 사진(흰 테두리) + 이름(송명) + 진영 도장 표시 + 등급(고정폭), 아래 설명과 "말투·참말일 때·거짓말일 때·세는 법"은 양식 두 칸(라벨 | 글).
- 못 만난 직업: 지금은 빗금 막대가 길게 이어진다. 진영별로 묶어 작은 뒤집힌 카드(마닐라 뒷면, "?")를 한 줄에 여러 장 놓는다. 그 직업이 어느 진영인지는 지금처럼 보인다.
- 화면 머리: 목차처럼 "인물 카드철" + 고정폭 "5 / 28".

수사 규칙
- 수사 지침서 한 장: 조항 머리 "제1조 목표"처럼(송명), 본문 목록은 여백 번호(고정폭)로. 개념 상자(concept)는 양식 두 칸(용어 | 설명)으로.

불러오는 중, 새 직업 카드(card-box)
- 불러오는 중: 코르크판 위 쪽지 한 장 "사건 서류를 꺼내는 중…".
- 새 직업 카드: 색인 카드(물건 사전).

## 8. 빌더에게 맡기는 것

- CSS 정리 방법(지금 style.css 한 파일에 덧칠된 규칙이 많다. 새로 쓰든 고치든 빌더가 정함), 변수 이름.
- 정확한 크기·간격·색 값(물건 사전과 실패 조건 안에서). 시안 값은 참고.
- Village Mono 부분 집합을 만드는 방법(지금 make-fonts 도구에 더하는 것이 자연스럽다)과 굵기 수(하나 또는 둘).
- check-ui 확인 항목을 새 구조에 맞게 옮기는 방법.
- 테이프·종이 기울기 같은 장식의 정확한 모양.

## 9. 다 됐다고 보는 기준

- 7장의 모든 화면이 물건 사전의 물건만으로 그려져 있고, 1장의 증상이 하나도 없다(코드에서 border-radius 999px, border-left 색 띠, 동그라미 숫자 규칙이 남지 않음).
- npm test, 타입 검사, 빌드, check-ui 전체 OK, check-offline OK. 글꼴 합계 보고.
- check-ui 스크린샷(타이틀, 스테이지 목록, 사건 3×3, 사건 30스테이지, 칸 메뉴, 결과, 도감, 규칙)을 사용자에게 보여 준다.

## 10. 빌더 눈으로 다시 읽고 정한 것 (Claude 판단, 사용자 확인 전)

- 화면 제목 문구는 지금 그대로(1스테이지, 무한 · 14번째 사건 등). 시안의 "사건 제14호"는 모양을 보이려고 쓴 예다. 무한 모드의 시드 줄은 제목 아래 고정폭 작은 글로 둔다.
- 서류철 표지 라벨의 양식 줄은 고정 문구 "사건 서류철 · 제1권". 시안의 "No. 0030"은 쓰지 않는다(뜻 없는 숫자).
- 결과 보고서의 사건 번호는 스테이지면 "사건 No. 01"처럼 두 자리, 무한 모드면 지금 제목 그대로. "다음 사건" 줄의 오른쪽 번호는 다음 스테이지가 있을 때만.
- 스테이지 목록의 "지금 할 것"은 풀린 것 중 아직 안 푼 가장 앞 스테이지.
- 사건 머리 양식의 명단은 지금 rosterSummary 와 같은 순서(주범 → 공범 → 말썽꾼, 직업표 순서).
- 이 설계의 빌더 검토는 별도 검토자 없이 Claude 가 직접 했다.
