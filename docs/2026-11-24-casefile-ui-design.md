# 마을 수사록 그래픽·UI 설계 — 수사 서류철

작성: 2026-11-24. 앞선 설계: docs/2026-11-23-village-case-design.md (게임 규칙·솔버는 그대로).

## 1. 왜 하는가

사용자가 출퇴근길에 폰으로 해 보니 "글자만 있으니 밋밋했다". 게임 규칙과 퍼즐은 그대로 두고, 화면을 그림과 분위기가 있는 게임으로 바꾼다. 목표는 몰입감: 형사가 사건 서류철을 넘기며 용의자 사진을 보는 느낌.

## 2. 목표 / 비목표 / 실패 조건

목표
- 모든 화면을 "수사 서류철" 한 가지 분위기로 통일한다(타이틀, 스테이지 목록, 사건, 결과, 도감, 규칙, 창·말풍선·알림).
- 직업 20개마다 서로 다르게 생긴 인물 사진(빛바랜 증명사진 느낌)을 둔다.
- 예쁜 글꼴: 제목 송명, 본문 고운바탕, 메모 나눔손글씨 펜.
- 짧은 연출: 조사하면 카드가 뒤집히며 사진이 나타나고, 체포하면 도장이 찍힌다. 결과 화면에 해결/실패 도장.

비목표
- 소리·음악 (출퇴근 중 폰으로 한다).
- 게임 규칙, 사건 생성, 솔버, 해설, 저장 형식의 변경.
- 다크 모드 (지금도 없음).
- 새 화면이나 새 기능 추가.

실패 조건 (돌아가도 실패로 본다)
- 글씨가 지금보다 작아지거나 장식 때문에 진술을 읽기 힘들어진다.
- 오프라인(비행기 모드)에서 글꼴이나 그림이 빠진다.
- 그림이 원작(Dupery)의 그림·화풍과 닮아 보인다.
- 인물 사진이 서로 비슷해 직업을 사진으로 구별할 수 없다(첫 시안에서 사용자가 지적한 문제).
- 폰(390×844)에서 가로 스크롤이 생기거나 누르는 자리가 44px 보다 작아진다.

## 3. 제약

- 화면 기준: 폭 390px 세로, PC 는 가운데 같은 폭(지금의 #app 최대 430px 유지). 양옆 여백 16px.
- 본문 글씨 15px 이상(지금 기준). 진술 줄은 지금보다 작지 않게. 손글씨 글꼴은 작아 보이므로 같은 글자 크기보다 크게 쓴다.
- 오프라인: 글꼴과 그림은 모두 앱 안에 넣고 PWA 미리 받기(precache)에 포함. 외부 글꼴 서버(Google Fonts)를 실행 중에 부르지 않는다.
- 용량: 글꼴은 게임에 실제로 나오는 글자만 남기는 부분 집합으로 만든다. 글꼴 셋을 합쳐 1MB 이하를 목표로 한다(넘으면 보고).
- 글꼴 저작권: 송명, 고운바탕, 나눔손글씨 펜은 모두 SIL Open Font License(무료, 앱에 넣어 배포 가능).
- 그림은 직접 코드로 그린 SVG. 외부 그림·AI 생성 그림을 쓰지 않는다.
- 동작 줄이기 설정(prefers-reduced-motion)이면 뒤집기·도장 연출을 끈다(지금도 그 설정을 따름).
- 화면 확인 도구(src/tools/check-ui.mjs)가 쓰는 data-* 속성(data-action, data-cell, data-stage, data-stat, data-result, data-hint, data-line, data-note, data-seed-msg)과 클래스 이름은 유지한다. 바꿔야 하면 check-ui 를 같이 고친다. 끝나면 check-ui 전체 OK.
- 시험(npm test), 타입 검사, 빌드는 그대로 통과.

## 4. 방법 (고른 것과 이유)

검토한 방법
1. 지금 화면(HTML·CSS, 직접 만든 DOM 도우미)에 새 모습을 입히고, 인물 사진은 SVG 를 코드로 둔다. — 고름.
2. 게임 엔진·캔버스(Phaser, Pixi 등)로 다시 그리기. — 안 씀. 글을 읽는 퍼즐이라 얻는 것이 없고, 오프라인 용량이 늘고, 다 만든 화면 로직을 다시 이어야 한다.
3. UI 라이브러리(Tailwind 등)를 새로 들이기. — 안 씀. 모습만 바꾸는데 화면 코드를 다 바꾸게 된다.

인물 사진을 만드는 방법(사용자가 1번을 고름)
1. 코드로 그린 SVG — 고름. 바로 만들 수 있고 용량이 거의 없고 화풍이 고르다. 나중에 그림 파일로 바꿔 끼울 수 있게 한 곳(사진 모듈)에서만 그림을 꺼낸다.
2. AI 생성 그림 — 안 씀(도구 필요, 20장 화풍 맞추기 어려움, 용량).
3. 무료 그림 꾸러미 — 안 씀(20개 직업에 맞는 같은 화풍 꾸러미가 없음).

## 5. 사용자가 정한 것

- 분위기: 시안 B "수사 서류철" (코르크판, 핀으로 꽂은 증명사진, 빨간 도장, 줄 공책 진술).
- 인물 사진 느낌은 좋다. 단 직업마다 확실히 다르게 생겨야 한다.
- 글꼴: 조합 "가" — 제목 송명(Song Myung), 본문 고운바탕(Gowun Batang), 메모 나눔손글씨 펜(Nanum Pen Script).
- 그림은 코드로 그린 SVG.

시안(docs/mockups/): 2026-11-24-casefile-screens.png (사건·타이틀), 2026-11-24-portraits.png (증인 8명 사진), 2026-11-24-fonts.png (글꼴), 같은 이름의 html 은 시안 원본(증인 8명 SVG 를 그대로 가져다 써도 된다). 색·재질은 이 시안이 기준이고, 6장의 색 값은 대략값이다.

## 6. 화면별 모습

색과 재질
- 코르크판: 갈색(#6f5136 부근) 바탕에 잔 점무늬. 사건 화면·스테이지 목록의 바탕.
- 종이: 미색(#f4efe4 ~ #fbf6ea). 카드, 진술 공책, 창.
- 마닐라지: 누런 빗금(#d8be8a 부근). 조사 전 카드 뒷면, 서류철 표지.
- 잉크 빨강(#b3261e 부근): 도장, 체포, 평판 강조. 지금의 남색 강조색은 버린다.
- 선·악 표시는 색만으로 구별하지 않는다(글자 "선/악", 도장 모양을 같이).

사건 화면
- 위: "‹ 나가기", 제목(예: 1스테이지, 사건 No.3)은 송명, 힌트 단추.
- 경과·평판·이번 사건 구성은 살짝 기운 메모지 한 장에.
- 이번 사건의 말썽꾼·악 직업은 꼬리표(태그 모양) 단추. 누르면 지금처럼 직업 창.
- 격자: 칸마다 핀으로 꽂은 사진 카드, 칸마다 살짝 다른 기울기(±2도 안). 칸 번호는 사진 왼쪽 위.
  - 조사 전: 마닐라지 뒷면, 가운데 "?", 아래 "조사 전".
  - 조사 후: 겉 직업의 인물 사진 + 아래 직업 이름(고운바탕).
  - 체포 후: 진짜 직업의 사진 + 이름 + 진영, 위에 빨간 "체포" 도장. 선을 체포했으면 도장 글자가 다르게(예: "오인 체포") 해서 선·악이 글자로도 보이게.
  - 메모(선·악·?)는 카드 귀퉁이의 노란 포스트잇, 손글씨. 표시만 하고 누르는 자리는 아니다(메모는 지금처럼 칸 메뉴에서 단다).
  - 누르는 자리는 카드 전체(기울기 전 상자 기준). 카드끼리 겹치지 않게 기울기와 간격을 잡는다.
  - 판 크기: 가로 3 ~ 5칸(무한 모드 최대 4×5). 칸이 좁아지면 사진을 줄이고, 글자는 지금 같은 판 크기에서 쓰는 크기보다 작게 하지 않는다(지금 4·5칸 판의 직업 이름 14px 이 하한). 이름이 길면 두 줄. 화면은 세로로 길어져도 되지만 가로 스크롤은 안 된다.
  - 힌트·안내가 가리키는 칸, 능력으로 고른 칸 표시는 지금처럼 유지하되 서류철 모습으로(예: 빨간 동그라미 표시).
- 진술: 줄 공책 한 장, 제목 "진술 기록". 체포로 정리된 줄은 빨간 줄 긋기 대신 지금처럼 선·악 꼬리표를 둔다(줄을 그으면 읽기 힘들다). 직업 이름은 점선 밑줄 단추(지금 기능 유지).
- 힌트·안내 말풍선: 포스트잇이나 쪽지 모양.
- 아래에서 올라오는 창(칸 메뉴, 직업 창): 종이 서류 한 장. 직업 창 머리에 그 직업 사진을 크게.

타이틀
- 서류철 표지: 마닐라 폴더 위 흰 라벨 "마을 수사록"(송명), 귀퉁이 "기밀" 도장.
- 메뉴는 종이 카드 + 왼쪽 빨간 띠: 사건 파일(스테이지), 끝없는 수사(무한 모드), 인물 카드철(도감), 수사 규칙(규칙). 지금 있는 단추·기능(이어 하기, 시드 입력 등)은 그대로 이 모습으로.

스테이지 목록
- 장마다 서류 묶음, 스테이지는 사건 파일 탭. 잠긴 것은 끈으로 묶인 모습이나 흐리게, 푼 것은 "해결" 도장.

결과 화면
- 해결이면 "해결" 도장, 실패면 "미해결" 도장이 크게 찍힌 수사 보고서. 해설 단계는 보고서 본문.

도감(인물 카드철)
- 만난 직업은 사진 카드 + 설명 + 말하는 방식. 못 만난 직업은 뒤집힌 카드(실루엣만, "?").

규칙
- 수사 규칙 문서(종이, 제목 송명).

연출
- 조사: 카드가 뒷면 → 앞면으로 뒤집힘(약 0.4초).
- 체포: 도장이 위에서 눌리듯 찍힘(약 0.25초, 살짝 커졌다 제자리).
- 결과: 도장 찍힘.
- 동작 줄이기 설정이면 모두 즉시 바뀜.

## 7. 인물 사진 20장

어떤 사진을 보이는가
- 체포 전 칸: 겉 직업(def.faces)의 사진. 위장한 공범·주범·숨은이는 증인 사진으로 보인다. 그래서 악 진영 사진의 어두운 바탕은 체포 전에는 절대 보이지 않는다.
- 체포 후 칸: 진짜 직업의 사진(지금 체포 칸이 진짜 직업 이름을 보이는 규칙과 같다). 도감: 그 직업 자신의 사진.
- 직업을 모르는 증인(ANY_WITNESS, '*w')은 화면에 겉 직업이 늘 구체 증인 직업으로 정해져 나오므로 사진이 따로 필요 없다. 만일을 위해 이름 없는 실루엣 하나를 대체 사진으로 둔다.

모두 같은 틀: 정사각형 사진, 가슴 위 상반신, 갈색조(세피아) 색, 사진마다 바탕색을 다르게. 직업마다 실루엣(모자·머리 모양·체격)과 소품이 확실히 달라야 한다. 사진 한 장은 SVG 하나, 직업 id 로 꺼낸다.

증인 8명 (시안에서 사용자 확인)
- 우체부: 우편모, 가방끈, 편지. 바탕 푸른 회색.
- 약사: 올림머리, 동그란 안경, 흰 가운, 십자 표시. 바탕 녹회색.
- 이장: 대머리와 옆머리, 콧수염, 양복·넥타이, 어깨띠. 바탕 갈색.
- 경비원: 휘장 달린 챙 모자, 넓은 어깨, 견장. 바탕 짙은 남회색.
- 빵집 주인: 높은 요리모, 통통한 볼, 앞치마, 바게트. 바탕 따뜻한 갈색.
- 사진사: 베레모, 얼굴 앞 사진기. 바탕 검정.
- 기자: 중절모와 명찰, 코트 깃, 수첩. 바탕 회색.
- 종지기: 두건, 흰 긴 수염, 종. 바탕 자주.

말썽꾼 4명 (빌더가 그림, 아래는 방향)
- 허풍쟁이: 과장된 몸짓, 큰 입·손짓, 화려한 나비넥타이.
- 길치: 지도를 거꾸로 든 모습, 배낭.
- 소문쟁이: 손을 입에 대고 속삭이는 모습, 머릿수건.
- 숨은이: 깃을 세운 코트로 얼굴을 반쯤 가린 모습.

공범 5명·주범 3명 (체포했을 때와 도감에서만 보임)
- 좀도둑: 눈가리개 복면, 줄무늬 옷.
- 협박꾼: 봉투를 내미는 손, 차가운 눈.
- 망보기: 쌍안경.
- 바람잡이: 확성기나 손뼉, 큰 웃음.
- 능청이: 한쪽 눈 찡긋, 비스듬한 모자.
- 두목: 중절모와 시가, 넓은 어깨.
- 그림자: 얼굴이 거의 안 보이는 검은 실루엣.
- 매수왕: 돈다발이나 금니, 화려한 정장.

악 진영 사진은 증인 사진과 같은 화풍을 지키되, 바탕색을 조금 더 어둡게 해 체포 화면에서 구별되게 한다(색 말고도 도장 글자로 구별).

## 8. 글꼴

- 제목·도장·큰 글자: 송명(Song Myung). 본문 길게 쓰지 않는다.
- 본문·진술·단추·설명: 고운바탕(Gowun Batang) 400·700.
- 메모·포스트잇·안내 쪽지: 나눔손글씨 펜(Nanum Pen Script), 같은 자리 다른 글씨보다 크게.
- 숫자가 많은 곳(경과·평판)은 고운바탕.
- 부분 집합: src 아래 문자열(ts, json, html)에 나오는 글자 + 영문·숫자·문장부호만 남긴다. 사용자가 입력하는 글은 시드 코드(숫자와 -)뿐이라 이것으로 충분하다. PWA 미리 받기 목록에 글꼴 파일 형식(woff2)을 더한다. 빌드 때마다 만들지, 한 번 만들어 넣어 둘지는 빌더가 정한다. 글꼴이 없는 글자가 나오면 시스템 글꼴로 보이게 대체 글꼴 순서를 둔다.

## 9. 빌더에게 맡기는 것

- CSS 구조(파일 나누기, 변수 이름), 사진 모듈의 모양.
- 말썽꾼·공범·주범 12명 사진의 세부 그림(7장 방향 안에서).
- 연출의 정확한 시간과 곡선.
- 스테이지 목록·결과·규칙 화면의 세부 배치(6장 방향 안에서).
- 글꼴 부분 집합을 만드는 도구.

## 10. 다 됐다고 보는 기준

- 6장의 모든 화면이 서류철 모습, 20개 직업 사진이 모두 있고 서로 구별된다.
- 오프라인(빌드 결과를 서비스 워커로 받은 뒤 네트워크 끊고) 글꼴·사진이 다 보인다.
- npm test, 타입 검사, 빌드, check-ui 전체 OK. check-ui 스크린샷으로 사건·타이틀·결과·도감 화면을 사용자에게 보여 준다.
- 추가 용량(글꼴+그림) 보고.
- 사진 20장을 한 장에 모은 대조표(contact sheet) 이미지를 만들어 사용자에게 보여 주고, 서로 비슷하다는 지적이 없어야 끝난다.

## 11. 빌더 검토 뒤 정한 것 (Claude 판단, 사용자 확인 전)

- 큰 판에서 글자 크기 하한은 "지금 같은 판에서 쓰는 크기"(6장 사건 화면).
- 포스트잇 메모는 표시만, 누르는 자리는 카드 전체.
- 직업 모르는 증인은 대체 실루엣 하나.
- 체포 전에는 겉 직업 사진만 보인다(7장).
- 진술 줄은 체포 뒤에도 줄을 긋지 않고 선·악 꼬리표를 둔다(시안과 다름, 읽기 쉬움).
- 선을 체포한 칸은 "오인 체포" 도장으로 글자로도 구별.
- 사진 대조표를 사용자에게 보여 주는 것을 끝 기준에 넣음.
